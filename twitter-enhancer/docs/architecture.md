# 运行时架构

改这块之前先读对应的源码头注释 —— 不变量和「为什么」都写在文件里，本文只做索引与红线。

## 启动链路

```
main.ts
├─ startDomWatch()    lib/dom-watch.ts   全站唯一 childList+subtree 观察器，派发 te:layout
├─ startRouteWatch()  lib/spa-route.ts   hook history API，派发 te:route
└─ for features       features/index.ts  按注册顺序 enable()
```

各功能只订阅事件、不自己 `new MutationObserver(document.documentElement)`。新增共享观察入口时也
收敛到这两个单例里（X 的虚拟滚动会让节点高频增删，观察器一多就是重复派发 + 掉帧）。

## 不变量

- **单一布局门控点**：`html[data-te-timeline='wide']` 一个属性同时决定三件事是否生效 ——
  CSS 宽度覆盖（`src/features/timeline-width.css`）、媒体高度钳制（`src/features/media-cap.ts` 的 `isActive()`）、
  宽度解锁器（`src/lib/unlock-width.ts` 的 `isActive()`）。所以「宽列不适用」的判定**只允许写在一处**
  （`src/features/timeline-width.ts`），撤销路径统一走 `disableTimelineLayout()`；不要在 CSS 里加 `:not()`、
  也不要在各模块里重复排除条件。
- **只放宽、从不收窄**：主列已经宽于目标时不碰（兜底判据 `alreadyWiderThanTarget()`）。
  必须在写 `data-te-timeline='wide'` **之前**读宽度 —— 那时 CSS 还没生效，读到的才是原生宽度。
- **适用页面按 DOM 结构判**：主列所在行里有右栏兄弟节点才算三栏页面，`/i/grok`（980 单栏）
  与 `/i/chat`（1187 双栏）交回 X 原生。不要改用「主列当前宽度」判据：SPA 切到 grok 时新主列
  会先以非原生宽度挂载，宽度判据在那一个瞬间会把它钉成 800。
- **左导航条不写任何样式**：X 自己的 fixed 定位已经与主列左缘对齐（`/home` 与 `/i/grok` 逐像素一致），
  覆盖它会让两个页面走两套摆放机制。
- **不移动/不重建 React 管理的节点**（除了 `CONFIG.search.mode = 'move'` 这条已知有风险的路径）。
  自建节点用 `te-` 前缀的 class 与 `data-te-*` 标记，撤销时按标记清理（注意 dataset 驼峰会转成
  连字符，选择器写 `[data-te-media-capped]` 而不是 `[data-teMediaCapped]`）。
- **禁止自反馈**：脚本自己写过的尺寸，永不再作为脚本自己的启发式输入。
  宽度解锁器按「计算宽度落在 600px 附近」推断锁死宽度，而媒体等比模式会把图片写成 608px ——
  数值一撞，解锁器就把脚本刚写的值改写成 `width: 100%`，图片被横向拉伸 1.6 倍。所以：
  **写几何的功能在写入处调 `markScriptSized()`（`src/lib/script-sized.ts`），
  按尺寸/样式推断的功能用 `isScriptSized()` 过滤**。新增功能照此办理，不要靠「再加一条豁免」。
  同一条禁令也管「读 X 的当前盒子或当前宽度」：
  - 等比盒子的高度曾经取 `min(预算, 宿主当前高度)`，而那个高度可能是 X 按我们上一轮写的宽度
    重算出来的（它的比例盒按盒宽算高度）—— 等价于拿脚本自己的输出当输入，同一帖会在不同加载里
    落到不同尺寸。现在恒取预算。
  - **「原生列宽」类实测只允许在我们自己的 CSS 未生效时做**：`data-te-timeline='wide'` 期间，
    SPA 导航新挂载的主列一进 DOM 就被我们的 CSS 写成目标宽，此刻读到的「原生宽度」其实是
    我们自己的输出 —— 解锁器判据区间会被整体挪到目标宽一带，列容器不再放开，
    时间线内容退回 600px 且一直坏到刷新（2026-09-14 用户实测）。判据：`teTimeline !== 'wide'`。
- **一条行只有一个宿主，且必须由同一个起点推导**：宿主 = 「媒体元素向上第一个够宽、
  不含正文的祖先」。**重新推导时必须从同一个媒体元素起算**（`findHost(media)`），
  从「上一轮的宿主」起算会得到它上面的一层，同一条行就在两级之间来回漂移
  （第一轮钳 A、增量重算却钳父层 B），排查时全是玄学。
- **增量路径只有一种输入：种子**（媒体元素或已钳宿主）。任何来源（滚动新增 / 媒体加载完成 /
  宿主里又长出一张图）都走同一条「解锁这条链 → 重新定位宿主 → 钳制」，
  不要按来源分叉：分叉的结果是某一类变化在增量路径上被静默漏掉（轮播成型曾如此）。
- **宽列只有两类代价，必须分开处理**（2026-09-14 实测，数据见 `docs/design-notes.md`）：
  1. **X 把「列宽」烘焙成了常量**（列容器与操作栏的 `max-width: 600px`）—— 它不随容器宽度
     自适应，只能由我们覆盖；覆盖**只允许用「选择器 + 角色」判定**（`unlock-width.ts` 的
     祖先链遍历、内容列版心），不引入任何测量。这一类至今没出过事故。
  2. **X 自适应，但结果不是我们要的**（宽列下媒体高过一屏、GIF 的 16:9 容器留黑边）——
     这是**产品决策**，必须测量才能覆盖 X 的输出。判据只允许用
     **「固有比例 + 行宽 + 预算」这类与被观察者无关的量**；
     **绝不能拿 X 当前给出的尺寸 / 结构当判据**：那是 X 计算的**结果**，
     拿结果当输入必然产生循环依赖与时序竞态（本文件下面「已修掉的坑」几乎每条都是这么来的）。
  实测依据：宽列下 X 自己的媒体比例永远正确（同一张图 976×867 与原生 596×530 比例一致），
  对它 dispatch `resize` 不产生任何重算 —— 「让 X 自己重算」这条路不存在，
  「一屏内看完」这类约束只能我们自己算。
- **宽列生效前的窗口不需要额外兜底**：`timeline-width` 应用宽度后一定会 dispatch `te:layout`，
  媒体钳制订阅它并做整列重算，因此「宽列未生效时到达的媒体」不需要重试定时器
  （曾加过一个 5s 重试，实测它是在给另一个缺陷打补丁；根因修掉后已删除，见 `design-notes.md`）。
- **按尺寸猜不如按角色判，而角色只能由结构给出**：解锁器放开的是「X 写死的列宽上限」，
  而列宽上限只可能挂在**列的祖先链**上。所以候选元素由**内容单元向上遍历**得到
  （`CONTENT_UNIT` = `cellInnerDiv` / `article[data-testid="tweet"]`），
  轮播格、图片容器、操作栏都在内容单元**内部**，永远不会成为候选 —— 一条判据取代了
  历史上那两张豁免表（轮播子树、脚本自写尺寸子树）。
  **不要写成「这个元素内部有没有内容单元」**：容器先于内容出现（X 先挂列容器、
  再往里渲染推文），那一刻谓词必然为 false，而扫过的祖先不会回看 ——
  实测后果是带 `max-width:600px` 的列容器始终不被标记，整列退回 600px（用户实测反馈）。
  遍历方向本身就是判据，就没有这种时序依赖。

## 已修掉的坑（别人已经踩过，别再踩）

- **SPA 导航闪烁**：切路由时 X 整棵重挂 app shell，功能写在旧节点上的内联样式随之丢失。
  锚点节点身份变化必须在 MO 回调里**同步**冲刷（早于渲染帧），等 120ms 节流就会出现
  「主列左移又回弹、左栏跳位」。
- **`/i/chat` 会 302**：`/messages` 跳到 `/i/chat/*`，其主列原生 1187px，旧逻辑的「放宽到 800」
  会把它压窄。路由判定要放在最前（不等主列挂载就先撤销开关），避免导航中聊天列被宽列样式画一帧。
- **document-start 时序**：`document.head` / `documentElement` 可能还没生成，样式无处可挂；
  真 TM 与 e2e 的注入位都在这时，必须先排队、等根节点出现再补挂。
- **主题检测**：document-start 时页面可能还是透明背景，不能据此误判成暗色主题。
- **后台标签页**：rAF 被冻结、定时器被压到 1s 甚至 1/min，所以调度器用 `setTimeout` 节流并在
  `visibilitychange` 回前台时补一次冲刷；长循环探测在这种环境下必然超时。
- **旧实现的教训**：「向上爬祖先找宿主」这类启发式必须考虑同一子树多次命中不同层级造成的
  叠加副作用（曾经的媒体双层缩放就是这么来的）。
- **按数值区间猜的启发式会被自己的输出带偏**：轮播格 562px、媒体等比链 608px 都落进
  `lockedWidthRange [560, 660]`，两次都把「尺寸像」当成「角色是」。见上面的
  「禁止自反馈」与「按尺寸猜不如按角色判」两条不变量。
- **拓扑判据不能问「里面有没有」**：容器先出现、内容后到达是 X 的常态（列容器 → 推文）。
  任何「内部含有某节点」的谓词都会在那一瞬间为 false，而扫描过的祖先不会再回看。
  要么让判据来自**遍历方向**（从内容向上），要么在内容到达时重新评估。
